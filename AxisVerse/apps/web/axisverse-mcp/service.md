# AxisVerse local material service

## Summary

This Python MCP service retrieves local course material and draws two-dimensional integration regions. DSH launches it over stdio through the [learning preset](../axisverse-presets/axisverse/agent.cordis.yml). Material queries are read-only; plotting writes PNG assets. The model receives excerpts and image references through persisted tool results; the whole corpus is not appended to its initial prompt. The [local user guide](../../../output/axisverse-study/接入说明.md) describes the installed app.

The learning preset also connects to the shared remote course-material MCP over Streamable HTTP, under the `course_materials` namespace. Connection details come from `AXISVERSE_COURSE_MCP_CONFIG`, or `~/.dsh/axisverse-course-mcp.json`, containing `url` and `headers` with the bearer authorization header. This private file must exist before activating the preset and must not be committed. The remote client uses a 60-second call timeout and reports startup failures. The local service remains available for the user's verified third-edition excerpts and plotting.

Remote queries explicitly select school, major, and course, and select a document after checking its edition. Test materials are not teaching evidence. Remote results provide PDF page references; they do not support the local `book_page` argument or the chapter's fixed page offset. The tutor distinguishes OCR text from verified formulas and does not silently substitute local results for failed remote requests. The browser uploads PDFs through the course-library host plugin. The shared POC does not provide per-student account isolation. Local PDFs remain available unless the exact document's remote ingestion and retrieval have been verified and its deletion authorized.

## Data and configuration

The interpreter must have the dependencies pinned in [requirements.txt](requirements.txt) installed: the MCP SDK, NumPy, and Matplotlib. The repository preset selects it with `AXISVERSE_MCP_PYTHON`, defaulting to `python`. Launch that template from the repository root: its prompt and server paths are relative to the process working directory. The installed user preset uses absolute paths instead.

`--corpus` is required and identifies the JSON catalog. `AXISVERSE_MATERIAL_PATH` overrides that JSON path in the repository preset. `--max-results` defaults to 5 and `--max-query-chars` to 200; the preset sets both explicitly. Tool calls have a 15-second client timeout and initial connection failure rejects preset activation.

`--asset-base-url` selects the public HTTP(S) directory for teaching diagrams, defaulting to `http://127.0.0.1:3082/axisverse/diagrams`. The repository preset exposes it as `AXISVERSE_ASSET_BASE_URL`. A deployment on another host or port must set this to the browser-reachable asset directory. Relative paths would be interpreted as workspace files by the current chat renderer. Credentials, query parameters, and fragments are not accepted in this base URL.

Repeat `--plot-output-dir` to enable plotting and select every static directory that receives generated images. The repository preset writes to both Web `public` and `dist` diagram directories: the running built app serves `dist`, and the next build copies retained images from `public`. Image names derive from conditions, window, sampling resolution, and renderer version; model arguments cannot select file paths. Each file is published with an atomic rename. Generated images are ignored by Git and must remain on disk for old conversations to display them.

`--plot-resolution` defaults to 401 points per axis and accepts 65–801. `--plot-font` selects an existing font file; the preset exposes it as `AXISVERSE_PLOT_FONT`. The font option remains accepted for existing presets; region diagrams contain no prose captions. Invalid configuration fails during service startup.

The catalog contains 17 manually verified excerpts from the supplied chapter photos, with printed page references and PDF page references. This format is specific to the supplied 53-page chapter: printed pages 130–182 map to PDF pages 1–53, and the first printed page is inferred. Book identity is user-reported. The service validates the file at startup and reloads it for every request. Missing files, malformed JSON, duplicate IDs, and inconsistent page references report service errors rather than empty search results.

## Tool behavior

The optional `course-library.mjs` host plugin provides the student material dialog with authenticated list and PDF-streaming routes. Its configuration names the private connection file, successful-upload receipt files, school, major, course, request timeout, and `pdfAssetsDirectory` pointing to the installed version-matched `pdfjs-dist` directory. Only document IDs recorded by those receipts can be listed or downloaded; this is an installation-specific uploaded list, not a claim of account isolation in the shared POC. Remote pagination is followed for metadata. Downloads use a retained original when available; other PDFs obtain a fresh short-lived remote URL, verify its origin, and stream through the host. The host's existing authentication and browser-trust checks protect every request. Remote errors return a generic unavailable response without credentials or signed links. The material dialog provides questions, section summaries, downloads and recoverable removal. The separate Add study materials panel uploads PDF bytes; neither dialog deletes remote documents. The authenticated `/view` route serves an HTML canvas reader with page navigation, zoom, and retries; it requests PDF ranges through the host and does not depend on popup support or a native PDF plugin. Reader resources and the PDF.js license are served from an allowlisted asset route; credentials stay on the host.

The [tutor prompt](../axisverse-presets/axisverse/tutor-prompt.txt) presents concept questions as an intuitive explanation followed by a precise definition and necessary notation. A missing direct excerpt receives one brief source notice; unrelated hits, search retries, and self-justifying claims about the assistant's restraint or honesty are omitted from ordinary teaching answers. Citations support only the associated claim, and an analogy to double integrals is not a source for a triple-integral definition. An unsuccessful search does not establish that a textbook page is absent from the corpus. These are model instructions, not deterministic output guarantees.

The student library omits trailing parenthetical photo-count and OCR-processing annotations from document titles and hides the configured generic upload-unit label. Chapter labels and PDF page counts remain separate metadata. Remote metadata and stored PDFs are unchanged. Authenticated `DELETE /api/axisverse/materials/{id}` stores a removal marker under the upload-receipt directory; removed entries are excluded from lists, previews, downloads and outlines across host restarts. `POST /api/axisverse/materials/{id}/restore` clears that marker. Both operations require an existing upload receipt and are idempotent. The card provides confirmation and immediate Undo, not permanent remote erasure; the remote service has no deletion endpoint. Re-uploading identical bytes restores the existing receipt-authorized entry without duplicating the remote file.

`list_course_materials` returns the title, coverage, page range, and excerpt directory. Directory entries do not contain the full excerpt text. `search_course_materials(query, book_page?, limit=3)` returns excerpt text and citations. The optional page is a printed page, not a PDF page; it filters both single-page excerpts and two-page ranges. Explicit `TB09` IDs also filter results. Otherwise matching uses curated keyword substrings and titles, with stable ID ordering for equal scores.

Results include `service_mode: local_mock`, `status: found | no_results`, counts, `has_more`, and `excerpts`. Each excerpt contains its ID, title, page references, text, and a ready-to-use citation. No hit means no matching verified excerpt in this catalog, not that the textbook lacks the topic. A returned excerpt may omit a requested exercise even when its page matches. The tutor must check the returned text before quoting an exercise or answer.

Selected excerpts also include `illustrations`, with public URLs, alt text, geometric explanations, and Markdown that makes the diagram itself a link to its full resolution. These are original teaching diagrams, not textbook scans. The tutor uses diagrams when the current explanation needs their geometry. An illustration in search results is optional; routine calculations do not automatically include a concept diagram. The tutor checks image URLs in conversation history and repeats a diagram only when the user asks to see or revisit it. Textbook or tutorial derivations receive a brief introduction once per problem; ordinary questions have no stock answer disclaimer. Empty illustration lists must not be described as displayed pictures. Each image contains one diagram and necessary mathematical labels, with no rasterized title, teaching paragraphs, or footer. The three available PNG assets cover spherical angles, spherical volume elements, and polar area elements. The two-panel integration-order demo is excluded from the catalog and generator; textbook example 3 remains searchable as text. Its historical image asset remains available for previously saved messages. The Web build copies them from [public assets](../public/axisverse/diagrams/); [render_diagrams.py](render_diagrams.py) constructs them using Matplotlib and NumPy, independently of the MCP runtime. The local generator selects Microsoft YaHei when installed.

`plot_integral_region(inequalities, x_min, x_max, y_min, y_max, integration_guides?)` draws the intersection of 1–8 inequalities using numeric sampling. It accepts `x`, `y`, `pi`, addition, subtraction, multiplication, division by a nonzero constant, integer powers 0–8, `sqrt`, and `abs`, with one `<`, `<=`, `>`, or `>=` comparison per condition. An arithmetic AST interpreter rejects other syntax; it does not execute model-supplied Python. The plot includes axes, condition labels, shading, and solid or dashed boundaries. The coordinate window determines the view, not additional mathematical constraints.

Generated region images use a square 1280 × 1280 white canvas with equal coordinate-unit scaling. Only geometry, axes, and mathematical labels are drawn; titles, explanatory prose, and sampling notices remain outside the image. Clipping and sampling information remains available in tool result fields. Inclusive curved boundaries use blue `#2563EB` at width 2.2; strict boundaries use grey `#6B7280` dashes; the intersection uses `#93C5FD` at alpha 0.35. Text uses `#374151`, coordinate axes and their ticks use black `#000000`, and the thin grid uses `#E5E7EB` at alpha 0.55. Equations are labeled directly on curves instead of a separate legend, with label anchors selected away from other curves and axes where space permits. Optional `integration_guides` contains at most eight derived boundary points `{x, y}`. Each receives a grey dashed segment from `(x, y)` to `(x, 0)`, a red point, and a tick at its x coordinate on the x axis. Affine single-coordinate constraints such as `x<=1` also use finite grey dashed segments, extending from their sampled feasible extent toward the corresponding coordinate axis; they keep their original inclusion predicates for shading. Coordinate limits have numeric axis ticks rather than equation labels. Limits and projections at `x=0` or `y=0` do not redraw or relabel the coordinate axes. Duplicate guide points and ticks are merged. These annotations do not change the shaded region or create additional inequalities. The viewport must include the x axis and every guide point; invalid positions are tool errors. Actual x-range constraints remain in `inequalities`. When the coordinate axes cross at the origin, only the x axis labels zero, offset to the lower left so the axis does not cross the glyph. Renderer versioning keeps earlier images available at their original URLs.

Successful results contain `status: plotted`, the conditions and window, a public image URL, Markdown, clipping and undefined-value information, and `is_exact_symbolic_solution: false`. A region touching the window edge produces a warning; undefined expression values are excluded. `no_visible_region` means sampling found no area in that window, not proof that the mathematical region is empty. Unsupported syntax and file-writing failures are tool errors. Narrow regions and exact intersections still require mathematical analysis. Three-dimensional plots, arbitrary functions, and symbolic solving are not provided by this tool.

The service does not provide full-text OCR, embeddings, material editing, user progress, answer keys, exam scope, or automatic PDF ingestion. Replacing it with a teammate's backend requires agreeing on tool names, arguments, result fields, and error semantics; incompatible responses need an adapter or prompt changes.

## Verification

The tutor stops after a brief explanation for unavailable pages, out-of-scope requests, and contradictory requirements. Such replies contain two to five sentences and at most one relevant next step. Derivations are limited to calculation, proof, or explicit requests; student answers omit internal fields, record counts, tool inventories, configuration, and credentials. Source citations retain textbook and PDF page numbers without internal record identifiers.

The nine tests in [tests/test_server.py](tests/test_server.py) cover real MCP stdio discovery and search, no hits, file disappearance, invalid arguments, catalog validation, overlapping page ranges, deployable diagram URLs, unillustrated excerpts, and rejected asset paths. Each test owns its temporary catalog; the SDK context owns subprocess cleanup.

The tests in [tests/test_region_plot.py](tests/test_region_plot.py) check half-disk orientation and approximate area, the region between a parabola and a line, unsupported syntax, undefined expressions, empty and clipped regions, image persistence, invalid windows, coordinate-limit styling and origin label deduplication, preserved strict constraints, and real MCP plotting. Temporary directories isolate generated assets. Run both files with `python -B -X utf8 -m unittest discover -s apps/web/axisverse-mcp/tests -v` from the repository root.

The [recorded-session case](../../../snapshots/session/axisverse-materials/snapshot.yml) replays an authored model exchange through the shipped headless profile and the real Python service. It checks successful retrieval, a missing page, a generated PNG, and persisted tool results. It mounts the shared tutor text as the headless system prompt; the installed Web preset is separately covered by the [material acceptance record](../../../output/axisverse-study/MCP验收记录.json) and [dynamic plotting record](../../../output/axisverse-study/动态绘图验收记录.json). Set `AXISVERSE_MCP_PYTHON` to an interpreter with the pinned dependencies to enable this optional local case; without it only this case is skipped. The verified local replay used `DSH_EXAMPLE_MODE=lib` and no model key.

## Browser PDF uploads

Uploaded materials retain their original filenames, including the extension. The library uses the original-file database name before a cached remote receipt name; remote processing titles do not overwrite that name. Downloads specify that name in the UTF-8 Content-Disposition filename. New remote ingestion receives the original filename as its title. Material questions record the displayed name as a link identifying the selected remote document, so existing OCR titles do not affect retrieval selection. Previously imported textbook entries without a saved upload filename retain their catalog title.

`POST /api/axisverse/materials/upload` accepts authenticated PDF bytes and an encoded `X-Material-Name` header. The host validates the filename, PDF signature and configured limit while streaming to disk, then records the original filename, hash and processing status in `materials.sqlite`. Schema version 3 adds ordered remote part IDs and original PDF page ranges to version 2 progress and failure codes; version 1 saved-only records migrate to failed, while unknown versions prevent startup. HTTP 202 confirms storage. Authenticated `/uploads` and `/uploads/{uploadId}` return actual queued, recognizing, indexing, ready or failed status. `/uploads/{uploadId}/retry` resumes a failed original without retransmission. Downloads stream the retained original for either its local or confirmed remote ID; questions and summaries require ready text.

A content hash deduplicates concurrent saves and confirmed remote ingestion. Original files, SQLite progress and OCR page checkpoints survive refreshes and host restarts. A single worker resumes interrupted jobs. Missing remote text or an oversized remote transfer invokes [recognize-pdf.py](recognize-pdf.py). The Windows helper recognizes scanned pages in bounded batches and constructs a compact searchable transfer copy; it preserves existing text pages, page count and page dimensions. The original remains unchanged. Completed-page progress comes from saved checkpoints, not elapsed time. OCR formula text needs comparison with the original page. Processing failures retain the original and a private diagnostic. A verified transfer copy survives remote failure, so retrying ingestion does not repeat OCR; successful ingestion removes that copy. Browser cancellation stops monitoring only; host disposal aborts and awaits subprocesses and remote requests before closing SQLite. Removing an entry also hides its eventual remote result.

Configuration requires `uploadCourse`, `uploadUnit`, `uploadReceiptsDirectory`, `maxUploadBytes`, `maxRemotePages`, `splitCommand`, `uploadTimeoutMs`, `ocrIdleTimeoutMs`, `uploadPollMs` and `ocrCommand`, alongside audience and connection settings. The OCR command receives source PDF, output PDF and checkpoint root; the split command receives searchable PDF, checkpoint root and the remote page cap. The installed Windows profile permits 500 MiB uploads, polls every 1500 ms, limits each remote operation to ten minutes and stops OCR only after 180 seconds without progress. Helper arguments configure OCR image size, batch size, transfer image size, JPEG quality, transfer-byte target and compression passes. Local originals stay on D:; the remote transfer copy targets 40 MiB. Local acceptance does not change the remote service limit. Confirmed receipts authorize documents across courses within the configured audience.

The shared remote library rejects PDFs above 500 pages with `TOO_MANY_PAGES`. [split-pdf.py](split-pdf.py) partitions a verified searchable copy at `maxRemotePages`, preserving page order and extracted text. Each confirmed part ID and contiguous original page range is committed before the next transfer; retries reuse confirmed parts and deterministic transfer receipts. The installation shows one original-name card and enables questions only when every part is searchable. Downloading returns the complete original. Questions persist links and original page ranges for every part; the tutor queries each separately and maps citations back to whole-PDF pages without adding unrelated fixed-course filters. Section outlines read every part and apply the same offset; explicit Chinese chapter/section headings and numbered decimal sections are recognized, including OCR spacing between Chinese characters. Missing titles are not invented. Removing the aggregate hides all its parts, including results completed after removal; restore makes them available together. Successful whole-book ingestion removes temporary transfer PDFs. Partial failures retain resumable copies and keep the original downloadable. PDF page offsets do not establish printed textbook page numbers.
